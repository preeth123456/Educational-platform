# Audit Logs & Security Trails - Setup Guide\n\n## Overview\nThis implementation provides comprehensive audit logging and security monitoring for the Eduyata platform, including:\n\n- **Activity Tracking**: All user actions (login, course access, profile changes)\n- **Security Event Logging**: Failed logins, suspicious activities, unusual IP access\n- **Data Access Audit Trail**: Who viewed student data when\n- **User-facing Activity History**: Timeline in Settings page\n- **Admin Audit Dashboard**: Compliance monitoring and security oversight\n- **Real-time Security Alerts**: Automated detection of unusual activities\n\n## Installation Steps\n\n### 1. Install Dependencies\n```bash\ncd django_backend\npip install -r requirements.txt\n```\n\n### 2. Create Database Tables\n```bash\npython setup_audit_system.py\n```\n\n### 3. Restart Django Server\n```bash\npython manage.py runserver\n```\n\n## Features Implemented\n\n### Backend Components\n\n#### 1. Database Schema\n- `audit_logs` table: Tracks all user activities\n- `security_events` table: Records security incidents\n- Proper indexing for performance\n\n#### 2. Audit System (`auth_app/audit.py`)\n- `AuditLogger` class for logging activities\n- Automatic suspicious activity detection\n- IP address tracking and geolocation\n- User agent analysis\n\n#### 3. Middleware (`auth_app/middleware.py`)\n- Automatic activity tracking for all requests\n- Real-time security event detection\n- Configurable action mapping\n- Performance optimized\n\n#### 4. API Endpoints\n\n**User Endpoints:**\n- `GET /api/auth/activity_history/` - User activity timeline\n- `GET /api/auth/security_events/` - Security events for user\n\n**Admin Endpoints:**\n- `GET /api/admin/audit_logs/` - Admin audit log access\n- `GET /api/admin/audit_summary/` - Audit statistics\n- `GET /api/admin/security_events/` - All security events\n- `POST /api/admin/resolve_security_event/` - Mark event as resolved\n\n### Frontend Components\n\n#### 1. Activity Timeline (`client/src/components/ActivityTimeline.tsx`)\n- User-friendly activity display\n- Real-time updates\n- Responsive design\n- Dark theme support\n\n#### 2. Settings Integration\n- New \"Activity History\" tab in Settings\n- Personal activity timeline\n- Security event notifications\n\n#### 3. Admin Audit Dashboard (`client/src/admin/AuditDashboard.tsx`)\n- Comprehensive security overview\n- Real-time statistics\n- Advanced filtering and search\n- Security event management\n- Compliance reporting\n\n## Security Features\n\n### Automatic Detection\n- **Multiple Failed Logins**: 5+ failed attempts in 15 minutes\n- **Unusual IP Access**: Login from new IP addresses\n- **Suspicious Patterns**: Rapid successive actions\n- **Data Access Monitoring**: Sensitive data viewing\n\n### Alert Levels\n- **Low**: Normal activities, informational\n- **Medium**: Unusual but not necessarily malicious\n- **High**: Potentially malicious activities\n- **Critical**: Confirmed security threats\n\n### Data Retention\n- Audit logs: Configurable retention period\n- Security events: Permanent until resolved\n- Performance optimization through indexing\n\n## Usage Examples\n\n### For Students\n1. Go to Settings → Activity History\n2. View personal activity timeline\n3. Monitor security events\n4. Check login history\n\n### For Admins\n1. Access Admin Dashboard\n2. Navigate to Audit & Security section\n3. Monitor system-wide activities\n4. Investigate security events\n5. Generate compliance reports\n\n## Configuration Options\n\n### Middleware Settings\nIn `settings.py`, the `AuditMiddleware` can be configured:\n\n```python\n# Customize tracked actions\nTRACKED_ACTIONS = {\n    r'/api/auth/login/': ('login', 'authentication'),\n    r'/api/courses/': ('access_course', 'course'),\n    # Add more patterns as needed\n}\n```\n\n### Security Thresholds\nIn `audit.py`, adjust detection thresholds:\n\n```python\n# Failed login threshold\nfailed_attempts >= 5  # Adjust as needed\n\n# Time window for detection\nINTERVAL 15 MINUTE  # Adjust as needed\n```\n\n## API Documentation\n\n### Activity History API\n```\nGET /api/auth/activity_history/?user_id=123&limit=50&offset=0\n\nResponse:\n{\n  \"status\": \"success\",\n  \"data\": {\n    \"activities\": [\n      {\n        \"action\": \"login_success\",\n        \"resource_type\": \"authentication\",\n        \"timestamp\": \"2024-01-15T10:30:00Z\",\n        \"description\": \"Successfully logged in\",\n        \"details\": {...}\n      }\n    ],\n    \"total\": 25\n  }\n}\n```\n\n### Security Events API\n```\nGET /api/admin/security_events/?severity=high&resolved=false\n\nResponse:\n{\n  \"status\": \"success\",\n  \"data\": {\n    \"events\": [\n      {\n        \"id\": 1,\n        \"event_type\": \"multiple_failed_logins\",\n        \"severity\": \"high\",\n        \"description\": \"User 123 has 5 failed login attempts\",\n        \"resolved\": false,\n        \"timestamp\": \"2024-01-15T10:30:00Z\"\n      }\n    ]\n  }\n}\n```\n\n## Troubleshooting\n\n### Common Issues\n\n1. **Tables not created**\n   - Run `python setup_audit_system.py`\n   - Check database permissions\n\n2. **Middleware not working**\n   - Verify middleware is in `MIDDLEWARE` list\n   - Check middleware order\n\n3. **No activities logged**\n   - Ensure user sessions are working\n   - Check middleware configuration\n\n4. **Performance issues**\n   - Verify database indexes\n   - Consider log rotation\n\n### Database Maintenance\n\n```sql\n-- Clean old audit logs (older than 90 days)\nDELETE FROM audit_logs \nWHERE timestamp < DATE_SUB(NOW(), INTERVAL 90 DAY);\n\n-- Archive resolved security events\nCREATE TABLE security_events_archive AS \nSELECT * FROM security_events WHERE resolved = TRUE;\n```\n\n## Compliance Features\n\n### GDPR Compliance\n- User data access logging\n- Data modification tracking\n- Right to be forgotten support\n\n### Educational Compliance\n- Student data access monitoring\n- Teacher activity tracking\n- Administrative oversight\n\n### Audit Trail Requirements\n- Immutable log entries\n- Timestamp integrity\n- User identification\n- Action traceability\n\n## Performance Considerations\n\n- Database indexes for fast queries\n- Asynchronous logging where possible\n- Configurable log levels\n- Automatic log rotation\n- Efficient JSON storage\n\n## Security Best Practices\n\n1. **Regular Monitoring**: Check security events daily\n2. **Threshold Tuning**: Adjust detection sensitivity\n3. **Log Retention**: Balance storage vs. compliance needs\n4. **Access Control**: Restrict audit log access\n5. **Backup Strategy**: Include audit logs in backups\n\nThe audit system is now fully implemented and ready for production use.
